AI 产品的模型决策交互
最好的形态可能是没有交互

AI 设计工作流
2026-07-26阅读约 7 分钟

作为 AI 用户，用大部分 AI 工具时，我都一直有个绕不开的问题：模型到底怎么选？不只是 AI coding 工具，生图、生视频工具也都有个选模型的动作。平时用 Claude vibe coding，出于省 token、又想要生成效率的双重考虑，经常会在切换 models 和 effort 上停几秒，多数时候其实也是凭感觉切。模型层面，我默认用 Claude Opus 5，遇到更复杂的设计任务才手动切到 Fable 5，管理类的活儿比如 GitHub 工作流就用 Sonnet 5；effort 层面，我基本很少动。

正好上周 Anthropic 和 Cursor 各发了一篇讲模型怎么选的文章，对用户来说，两种方式截然不同。Anthropic 是教你怎么选，而 Cursor 在 AI 工具层早就替你选好了。这是我觉得 Cursor 很有产品 sense 的点：真实解决了用户的难点，自动路由又是个很妙的产品设计策略。

自动路由不是 Cursor 首创，ChatGPT 一年前就内置了 GPT-5 router，只不过走的是完全内部路由，表现层的用户完全不知情。但这套全自动没扛住：router 一度不稳，又撤掉了手动选模型的入口，招来用户一片不满，又很快把 model picker 加了回来。绕了一圈，又退回到「默认自动、但随时能接管」。现在，又出现了同样的产品策略，Cursor 做的是在两种体验中结合了，而 Claude 是更加保守的做法。

手动选模型
选择权在用户

以 Anthropic 为例，思路是先把模型分档：最前沿的 Fable 留给硬骨头，那些从没解过的难题、长链条的 agent、复杂 coding；Opus 适合重推理的企业任务，比 Fable 快也便宜；Sonnet 可以是日常主力，也最适合拿来跑大批量的子 agent；Haiku 最便宜最快，给那种高频、对延迟敏感又不难的活儿。

官方给的默认建议是，先从当前能用到的最聪明的模型起步，再用 effort level 去调性能和成本。因为高能力模型虽然单 token 贵，但常常几轮就做对了，单次任务算下来反而更省。判断到底选哪档，它拆成几个问题：任务有多难、对延迟敏不敏感、跑到量产之后单次成本合不合算。

有个日常使用方式：让快的模型干主力，偶尔叫更强的模型来当顾问过一眼。比如，Sonnet 5 配一个 Fable 5 当顾问，分数能到 Fable 5 的九成以上，价钱只要 63%。它还特意提醒别只看 benchmark，顶尖模型早把榜刷到饱和了，要在几个最强的模型中分高下，还是得看自己生产环境里的任务建一套评测。

Anthropic 这套逻辑可以理解，不过它还是站在「用户自己怎么判断」的角度。这让我联想到互联网产品设计里的「引导、说明」机制：其实没多少用户会仔细看，实操时也不太会照着做。

自动分配模型
帮用户做困难决策

像 Anthropic 这种把决策权交给用户，用户会更有深度参与感；而像 Cursor 这种自动 router，把每个请求分配到最适合当前任务的模型，决策权交给产品，也是一种让用户以更低成本使用 AI 的方案。不过同时，Cursor 把这个能力定位成面向团队和组织开放，Auto Intelligence 的权限给了管理员，某种程度上也算把选择权交回给了用户。

Cursor Router 背后的设计动因，是他们发现大约 60% 开发者日常就靠一个前沿模型干所有活，routine 任务也按旗舰单价在跑，而 AI 支出的增长速度远快于输出质量的提升。

Cursor 的优势在于对用户偏好以及哪些内容最终能留在代码库中有着独特洞察，同时了解每个模型最擅长的场景，因此可以将请求路由到最合适的选项，这件事情非常适合 Cursor 来做。

Cursor 拿数百万条真实请求做在线 A/B 测试（不是离线跑分），Router 省下约 60% 成本，同时还给到前沿质量。输出质量有两个方面：用户满意度和代码保留率。几个早期高用量账户实测，比全程用 Opus 4.8 省了约 30%–50%。跟 Fable 比，Auto Intelligence 满意度接近 Fable、成本却低约 60%；跟 Opus 4.8 比，是在成本几乎持平的前提下，满意度高出约 15%。

它本质是个分类器，为了分得准，用六十万条真实请求训出来，每个请求进来先看内容、上下文、任务复杂度和领域，再决定派给哪个模型。拿设计工作流来说，简单活给便宜模型，纯 UI 更新给擅长审美的那档，复杂长链条的才上前沿推理模型。Cursor 把它设成三挡：Intelligence 对齐最强模型的质量，Balance 对标日常够用的水准，Cost 主打省 token。

AI 产品设计
别把复杂交给用户

传统互联网设计里有一条：Don't make me think，尽量减少用户的疑惑和流程摩擦，让用户少动脑子。而在 AI 产品设计里，真正 make me think 的，是「该用哪个模型、会花多少成本」这种本来得靠专业经验的判断。Anthropic 和 Cursor 给的两种不同的产品答案，也都各有角度：

•产品设计层面，Anthropic 倾向于给判断框架、教用户怎么用，前提是用户愿意投入进来。Cursor 更自动化，它不觉得用户必须懂模型分类，而是把这个决策做成了产品的默认能力。Cursor 的产品 sense 就在这：与其教用户怎么选，不如替用户把这件麻烦事消化掉。

•模型产品设计层面，选模型正在被塞进不同的层。GPT-5 一年前就把 router 做进了模型系统内部，用户在 ChatGPT 里连模型都看不到，走快模型还是推理模型由它实时判断；Cursor 把 router 做在应用层，用户挑的是 Intelligence / Balance / Cost 三挡意图，而不是具体型号；Anthropic 把选择留在最外面，什么都不替用户决定。放在哪一层，是每个产品取舍：越靠近模型内部，用户越省心，透明度也越低。

•体验设计层面，自动路由省掉的是操作步骤，代价是可预测性和掌控感。GPT-5 的 router 上线后，不少人不满意看不到自己到底用了哪个模型，OpenAI 到现在还给付费档留着手动 picker。自动化也不能只省钱省事，还得让用户想决策时能决策、想看时看得到里面发生了什么。Cursor 留了三挡、又让管理员能锁模型，就是在替你决定和让你掌控之间找平衡。

最后回到我自己的设计工作流：琐碎活交给一个默认挡去跑，需要设计判断的地方再手动切最强模型。但更理想的状态，是连「该用哪个模型、花多少 token」这些念头都不用起，也不用手动切来切去。最精简的 AI 产品设计，是把模型和成本这层复杂度整个吞进产品里，让用户只管表达意图、不必为效率分心。 到那一步，token 效率不再需要用户自己去算，AI 产品默认就给出了最划算的那条路线。
